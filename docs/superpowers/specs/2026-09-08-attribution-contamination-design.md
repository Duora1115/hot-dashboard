# 归因污染修复设计（板块 / 多空 / 幽灵股）

- 日期：2026-09-08
- 状态：待 review
- 涉及：`backend/collector.py`、`backend/data_store.py`、`config/settings.yaml`、`scripts/`、`src/`

## 1. 背景与问题

线上站点 touyan.fun 的个股卡片 / 详情里，板块标签与多空统计存在系统性失真。定位到**三类独立问题**，只修其一都会留下残余症状。

### Bug B（本仓库代码）——整条消息级关键词归因
- `backend/collector.py:265 analyze_text` 对**整条消息**扫描板块 / 情绪 / 操作关键词，命中即挂到这条消息上。
- `backend/collector.py:299 compute_snapshot` 再把一条消息命中的**全部板块并集到该消息提到的每一只股票**（`:371-374`）；多空同理，把消息级布尔值贴给消息里的每只票（`:349-350`）。
- 结果：任何被"大盘综述"顺带提到的票，都会被贴上消息里出现的所有板块。
- 实例：海康威视（正常提及）因一句"白马红利…"被打上"银行"——`settings.yaml:94` 里 `红利` 属于银行关键词。

### Bug B2（词库）——关键词本身过宽 / 错放
- 词表把风格因子、通用词、跨行业词混进板块：`红利`/`高股息`⊂银行、`华为`⊂AI算力、`推理`/`训练`/`牛市` 等通用词，以及 `消费`⊂`消费电子` 的子串误匹配。
- 这类污染**邻近归因（B1）治不了**：词就在窗口内。需单独清理词库，见 3.1.1。

### Bug A（上游数据）——链接把题材词错认成个股
- 群消息里带飞书 / 发帖端生成的 eastmoney 链接 `[文字](…/stock/市场.代码.html)`。链接文字是发帖人的简写，可能指向**题材词**而非个股。
- 实例：`[农业](…/1.601288.html)`——上下文是"厄尔尼诺 / 鱼粉 / 中水 / 百洋"，讲的是**农业题材**，但链接指向 601288 = 农业银行，产生幽灵股。
- 链接在进入本系统前就已存在，非本仓库生成。

### 影响面
`sec` 由 `backend/data_store.py:48` 映射进 API，前端 5 处消费：`src/types/api.ts`、`src/lib/aggregate.ts`、`src/pages/StockDetail.tsx`、`src/pages/Dashboard.tsx`、`src/pages/Sectors.tsx`；`top8_sectors[].s`（板块→成分股）也依赖它（`data_store.py:56-60`）。

## 2. 目标 / 非目标

**目标**
- 板块 / 多空 / 操作**按股票就近归因**，消除整条消息串味。
- 拆分"所属板块"与"消息关联板块"两个字段。
- 丢弃链接文字命中歧义清单的伪提及（Bug A）。
- 顺带清理最离谱的高危关键词 + 子串误匹配（Bug B2，范围见 3.1.1）。

**非目标**
- 不引入外部行业分类（第二步再做）。
- 不处理"只有名字、没有链接或代码"的提及（现状，记为已知限制）。
- 不改热度公式。

## 3. 设计

### 3.1 配置（`config/settings.yaml` 新增）
```yaml
attribution:
  window_chars: 30             # 股票提及前后 ±N 字符
  ignore_link_texts: ["农业"]   # 链接文字命中则丢弃该提及（可回滚）
```

#### 3.1.1 高危关键词清理（B2）
邻近归因（B1）无法消除**词库本身错误**导致的污染——实测海康威视触发 `('银行','红利')`，因为 `红利` 被错放进 `银行`。本期只动最离谱的几个，其余留给第二步的外部行业映射：

| 板块 | 现有关键词 | 改动 | 原因 |
|---|---|---|---|
| 银行 | `银行 银行板块 高股息 红利 息差 不良` | 移出 `红利`、`高股息`、`不良` | `红利`/`高股息`是风格因子，非银行；`不良`过于泛化 |
| 高股息（新） | — | 新增 `["高股息", "红利", "股息率"]` | 承接移出的词，保留信号；前端板块列表为数据驱动，加板块无需改代码 |
| AI算力 | `AI 算力 昇腾 华为 大模型 GPU … 推理 训练 …` | 移出 `华为`、`推理`、`训练` | `华为`归消费电子/汽车；`推理`/`训练`是通用动词，误伤大 |
| 券商 | `券商 证券 牛市 …` | 移出 `牛市` | 大盘级词汇，非券商专有 |

清理后板块数 18 → 19。前端 `Sectors.tsx`/`Dashboard.tsx` 均从快照读取板块列表，无硬编码枚举或色板，新增板块零改动。

### 3.2 归因算法（`collector.py` 新增 `attribute_message`）
1. **链接提取**：正则 `\[([^\]]+)\]\(https://wap\.eastmoney\.com/quote/stock/\d\.(\d{6})\.html\)` → `(link_text, code, span)`。
2. **丢弃**：`link_text ∈ ignore_link_texts` → 跳过该提及。
3. **裸代码**：在链接 span 之外的 `\b[36890]\d{5}\b` 也算提及（`link_text=""`，高置信）。
4. **逻辑文本**：构造一份"逻辑文本"——把每个 `[文字](url)` 折叠成 `文字`（长 URL 不计入距离），并记录每个 code 在逻辑文本中的位置。窗口距离一律基于逻辑文本，否则一条 100+ 字符的链接会撑爆 ±30 窗口。
5. **切句**：在逻辑文本上按 `。！？；!?;`、换行、以及 ≥2 个连续空格切分。
6. **取窗**：某提及的判定范围 = 所在句 ∩ `[pos-N, pos+N]`。
7. **扫描**：窗口内匹配板块 / 情绪 / 操作词，归到该 `code`。匹配用**最长优先去重叠**：把所有命中按关键词长度降序，已接受的长命中覆盖区间内不再接受短命中（消灭 `消费`⊂`消费电子` 这类嵌套误匹配）；ASCII 关键词（`AI`/`GPU`/`PCB` 等）加 `\b` 词边界，避免 `ai`⊂`said`。
8. 输出 **per-code 归因**。

`analyze_text` 扩展：新增 `by_code`；保留原 `codes` / `sectors` / `sentiments` / `actions`（消息级，供 `ms` 与板块热度、整体情绪使用）。

### 3.3 快照字段（`compute_snapshot` / `data_store._compress_snapshot`）

| 字段 | 来源 | 用途 |
|---|---|---|
| `sectors` → `sec` | `by_code` 邻近板块并集 | 所属板块：卡片标签、同板块对比、Sectors 归属 |
| `mention_sectors` → `ms` | 消息级板块并集（旧逻辑） | 该消息整体涉及的题材（非"共振"，见下） |
| `bull` / `bear` | `by_code` 邻近情绪 | 多空统计 |
| `action_count` | `by_code` 邻近操作 | 热度输入 |

- 热度公式不变：`groups*3 + mentions*2 + actions*5 + (bull-bear)*2`。
- `top8_sectors[].s`（成分股）改用 `sectors`（所属），使板块页成分股变准。
- API 只**新增** `ms` 字段；老 day 文件没有它 → 前端按空数组处理。
- **`ms` 保留**：它是"这条消息整体聊了哪些题材"，对多票同题材的消息仍有信息量；B2 清理后噪声显著下降。但它是**消息级并集**，不等于"该股与这些板块共振"，前端文案不写"共振"以免误导。

### 3.4 前端
- `src/types/api.ts`：`StockItem` 加 `ms?: string[]`；`sec` 注释改为"所属板块"。
- `src/lib/aggregate.ts`：合并快照时 `sec` / `ms` 均并集。
- `src/pages/StockDetail.tsx`：头部标签用 `sec`；"关联板块"面板拆成"所属板块"（`sec`）与"消息关联板块"（`ms`）；同板块对比改用 `sec`。
- `src/pages/Dashboard.tsx` 卡片标签、`src/pages/Sectors.tsx` 归属：用 `sec`。

### 3.5 重算脚本（`scripts/recompute.py`）
- 读 `msg_cache.json` → 按天重建 `day_<date>.json`（复用同一 analyze / compute 管线）。
- **前置校验**：确认远端 `msg_cache.json` 是否仍保留全部原始消息（本地这份仅覆盖 6/03–7/08、5 个群）。不满足则只能前向，不做历史重算。

### 3.6 测试
- 新增 `tests/test_attribution.py`：窗口内 / 外归因、切句、逻辑文本折叠（长 URL 不撑窗）、`ignore_link_texts` 丢弃、单条消息多票不串味、裸代码、最长优先去重叠（`消费`⊄`消费电子`）、ASCII 词边界（`ai`⊄`said`）。
- 新增 B2 回归：含"红利"的海康消息归因结果不含 `银行`；`settings.yaml` 关键词表与 3.1.1 一致。
- 现有 `tests/` 保持绿（`test_collector.py` 的 `bull` 断言中关键词与提及相邻，邻近归因仍成立）。

## 4. 兼容性 / 回滚
- `ms` 为新增可选字段，前端容错。
- `ignore_link_texts` 可在配置里增删，回滚即恢复。
- 历史 day 文件在重算前保持旧语义（新旧短暂混杂，需接受）。

## 5. 已知限制
- 纯名字 / 无代码提及不计入股票统计。
- 歧义清单需人工维护，可能误伤（可通过回滚修正）。
- 词库仍是手工维护。B2 只清了最离谱的几个（红利/华为/牛市/推理/训练…）；`AI`、`资源` 里的单字词（`铜`/`铝`）等泛化词未动，仍可能误伤，留待第二步。
- 第二步（引入外部行业映射，把"所属板块"做成权威分类）不在本期范围。
