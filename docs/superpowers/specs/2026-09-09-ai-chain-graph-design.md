## 1. 背景与目标

现有站点按"热度"看个股与板块，但个股之间是孤立的——看不出"谁和谁在一条链上""上游涨价会传导到谁"。用户要一张类 Obsidian 的关联图谱，把 AI 产业链上的上市公司按关系连起来。

**目标**
- 新增 `/chain`「产业链图谱」页，展示 AI 产业链上市公司之间的关系。
- 四种关系全部表达：**同一环节（同业）/ 上下游供货链 / 生态阵营 / 铲子层级**。
- 叠加当日热度：节点大小 = 当日热度，今日被群提到的票加描边。
- 服务两种用法：**结构导航**（看产业链布局）与**交易信号**（从今日热票顺链找"同链未上榜"的补涨候选）。

**非目标**
- 不引入行情/涨跌幅数据（本期只用群消息热度）。
- 不做自动抽取管线：关系数据一次性抽取后手工维护。
- 不覆盖全市场，只覆盖报告点名的 AI 产业链上市公司。
- 不改现有页面与后端。

## 2. 数据模型

新增 `src/data/ai_chain.json`，随前端打包（无后端改动），手工维护。

```jsonc
{
  "meta": { "source": "AI基础设施产业链深度报告", "updated": "2026-09-09" },
  "segments": [
    {
      "id": "光模块",
      "name": "光模块",
      "tier": "直接铲子",
      "upstream": ["光芯片", "PCB"],     // 供应商方向的相邻环节 id
      "downstream": ["交换机", "服务器"] // 需求方向的相邻环节 id
    }
  ],
  "stocks": [
    {
      "code": "300308",
      "name": "中际旭创",
      "segment": "光模块",            // 主环节 id，决定颜色/聚类
      "ecosystems": ["英伟达链"],      // 阵营，可多个
      "tier": "直接铲子",              // 缺省继承所属环节的 tier
      "role": "800G/1.6T 光模块龙头"   // 一句话角色
    }
  ]
}
```

字段约定：
- `segments[].id`：环节唯一标识，也是 `stocks[].segment`、`upstream`、`downstream` 的引用目标。
- `tier` ∈ {`直接铲子`, `间接铲子`, `铲子的铲子`}（报告"铲子三层论"）。
- `ecosystems`：阵营标签，推荐词表 {`英伟达链`, `华为链`, `北美CSP链`, `国产算力链`}，允许按需扩展。
- `stocks[].tier` 可选，缺省继承所属环节的 `tier`。
- `code`：6 位 A 股代码，必须存在于 `backend/stock_mapping.json`。

## 3. 关系派生规则

四类关系全部由上述数据派生，不重复存储：

| 关系 | 来源 | 图上表现 |
|---|---|---|
| 同业 | 同 `stocks[].segment` | 同环节聚类内的细线，默认淡显，选中节点时加亮 |
| 上下游 | `segments[].upstream` / `downstream` | 环节簇之间的聚合弧线，默认关，可开 |
| 阵营 | `stocks[].ecosystems` 有交集 | 跨环节连线，默认关，可开 |
| 铲子层级 | `stocks[].tier`（缺省继承环节） | 过滤器 + 节点描边样式 |

说明：上下游在报告里是**环节级**关系（如"电子布→CCL→PCB"），不是公司到公司，因此图上画成环节簇之间的弧线，不做公司两两连边（否则边数爆炸）。

## 4. 抽取规则与人工审核

抽取在实现阶段由 AI 执行一次，产物 `ai_chain.json` 提交前须经用户过目。

1. **环节**：取自报告章节结构（算力芯片 / 芯片制造设备 / 芯片制造材料 / 探针测试 / 量检测 / 封测 / 机架 / 铜连接 / 光模块 / 交换机 / 服务器整机 / 算力租赁与 IDC / PCB / CCL / 电子布 / 铜箔 / 树脂 / 电力 / 液冷 …）。具体清单以实现产物为准。
2. **公司 → 代码**：用 `backend/stock_mapping.json` 反查（名称→代码）。查不到的（华为昇腾、阿里平头哥等未上市）**排除**。
3. **歧义名**（如"华勤"↔"华勤技术"）：宁可漏掉也不猜；漏掉的在提交说明里列出，由用户补。
4. **阵营、铲子层级、role**：从报告原文取；role 限一句话。
5. **环节上下游**：从报告对环节间传导关系的描述归纳。

## 5. 页面与交互

新增路由 `/chain`「产业链图谱」，加入导航。整页一块力导向画布 + 顶部过滤条 + 右侧详情栏。

```
┌────────────────────────────────────────────────┬──────────────┐
│ [环节▾] [阵营▾] [层级▾] [搜索____] [高亮同链未上榜] │  中际旭创     │
│                                                  │  300308       │
│        ● 光模块簇      ● 芯片簇                  │  环节: 光模块 │
│       ●   ●           ●   ●                      │  阵营: 英伟达链│
│         ● ●  ~~~~上下游弧线~~~●  ●                │  层级: 直接铲子│
│        ●   ●                                   │  今日: 热度 42 │
│           \____阵营线____/                       │  看多3 看空1  │
│        ● PCB材料簇     ● 机架簇                  │  [→ 个股详情]  │
│                                                  │  同环节邻居…  │
└────────────────────────────────────────────────┴──────────────┘
```

**节点编码**
- 大小 ∝ 今日峰值热度（该股在今日全部快照 `stk` 中的最大 `sc`；未上榜则 0，用固定小尺寸）。
- 颜色 = 主环节（确定性调色板，见 §6）。
- 今日上榜（至少出现在一个快照的 `stk` 中）的票加描边；悬停显示名称 + 今日峰值热度。
- 今日未上榜的票**暗显**（降低透明度 + 虚线边框），与上榜票形成对比；这是"补涨候选"的视觉基底。
- 画布左下角固定图例，说明三类边的线型与"节点大小 = 当日峰值热度"。

**边（三类，各自可开关）**
- 同业：默认开（淡显），选中节点时加亮其同环节边。
- 上下游：默认关。
- 阵营：默认关。

**交互**
- 点击节点 → 高亮其同环节 + 同阵营邻居，其余变暗；右侧栏展开（角色、今日峰值热度、累计提及/多空、`[→ 个股详情]` 跳 `/stock/:code`）。
- 顶部过滤：按环节 / 阵营 / 层级多选筛节点；搜索框按名称或代码定位。
- **「高亮同链未上榜」开关**：选中一只今日热票后，同环节里**今日未进过热榜（Top10）**的票加琥珀色发光描边 + 「补涨候选」小标签——"从热票顺链找补涨候选"的核心动作。口径见 §8。
- 拖拽移动节点；点击空白取消选中。

**窄屏（视口 < 768px）**
- 保留力导向画布，**不是**降级成列表：支持拖动平移 + 双指缩放（`react-force-graph` 原生支持）。
- 标签策略：只渲染热度 ≥ 60 的节点 + 选中节点 + 其同环节候选，其余只留圆点；环节名以彩色小字标在簇旁（避免 360px 下文字糊成一片）。
- 图例改为画布底部横向滚动的色点条；详情不再用右栏，改为**底部精简卡片**（名称/代码/环节/阵营/热度/多空 + 「详情」），点「详情」展开完整抽屉。
- 提供「图谱 / 列表」视图切换：列表 = 按环节分组的行（组头 = 色点 + 环节名 + 只数，行 = 名称/代码/热度条，未上榜行灰显无热度条），默认「图谱」。两种视图消费同一份派生数据，切换只换渲染层。

## 6. 数据流与技术选型

**数据流（无后端改动）**
- `src/data/ai_chain.json` 静态打包，`/chain` 路由按需加载（code-split）。
- 今日热度从 `useStore.currentDayData.snapshots` 取整日快照，遍历各快照 `stk`（`StockItem`: `c/sc/mc/bu/be`），按 `c` 汇总出每股**峰值 `sc`**、**今日上榜集合**，以及最后一次出现快照的累计 `mc/bu/be`。
- 合并：每个节点查汇总结果；未上榜 = 峰值 0、小尺寸、无描边。
- 合并、派生边、配色都放在 `src/lib/chain.ts` 的纯函数里，便于单测/复用。

**技术选型**
- 图渲染：`react-force-graph-2d`（canvas + d3-force，几百节点流畅，支持自定义绘制节点/边与聚类力）。备选：d3-force 自绘（代码多些）、cytoscape（更重）。依赖只进 `/chain` 分包。
- 配色：现有 app 无环节色板（板块为数据驱动），新增固定调色板，按 `segments` 顺序确定性分配（手加环节时既有颜色不变）。
- 改动面：新增 `src/pages/Chain.tsx`、`src/lib/chain.ts`、`src/data/ai_chain.json`；改 `src/App.tsx`（路由）、`src/components/Navbar.tsx`（入口）。

## 7. 测试与维护

- **pytest 一条**：校验 `ai_chain.json` —— 每个 `code` 存在于 `backend/stock_mapping.json`；每个 `segment`/`upstream`/`downstream` 指向已定义环节 id；`code` 不重复；`tier` 取值合法。这是唯一的自动化测试（前端无测试框架）。
- `npm run build` + 类型检查。
- **浏览器手动验证**：过滤、三个开关、点击高亮、同链未提及、空数据日、窄屏降级。
- **维护**：直接手改 `ai_chain.json`；校验测试兜底。

## 8. 风险与已知限制

- **React 19 兼容性**：`react-force-graph` 对 React 19 的兼容需在实现第一步验证（装包 + build）；不行则退回 d3-force 自绘，接口不变。
- **抽取质量**：名称→代码映射可能漏配/错配；歧义宁漏不猜，产物交用户审核。
- **图上拥挤**：上百节点默认只开同业边；上下游/阵营按需开。
- **上下游粒度**：是环节级，不是公司到公司。
- **覆盖范围**：只有报告点名的公司；未上市排除。
- **热榜口径**：`stk` 只有 Top10，所以"上榜"= 今日进过 Top10，**不等于"被群提到过"**；未上榜的票也可能被提过一两次，只是没进过热榜。侧栏与开关文案按"上榜/未上榜"表述，不写"未提及"。
- **热度依赖当日快照**：无快照（如盘前）时所有节点无高亮、等大。

## 9. 兼容性 / 回滚

- 纯新增页面与静态数据，不动现有页面、类型、后端。
- 回滚：移除 `/chain` 路由与导航入口即可，其余文件孤立无害。
